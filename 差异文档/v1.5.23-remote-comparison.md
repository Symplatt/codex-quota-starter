## 功能

### F1：拖动时间轴设置计划

原来仅通过“选择时间”弹窗设置刷新时间；现在增加可拖动、可使用左右方向键的发送节点。步长为600秒；原时间不在十分钟格点时，第一次按操作方向吸附。拖动中的画面只作预览，松开后调用原有计划接口保存；取消拖动不保存。弹窗仍支持整分钟，不受十分钟步长限制。

```text
目标发送时间 = 按拖动方向吸附到十分钟格点(原发送时间 + 位移对应时长)
目标发送时间 = 限制在当前允许的发送范围内(目标发送时间)
拖动期间：显示目标发送时间与其后五小时的预计刷新时间
松开：调用计划接口保存
取消：还原显示，不调用保存接口
```

实现位置：远程 `ui.html` 的 `dragSendTarget`、时间轴拖动事件及 `#timeline-handle`。计划允许范围、防重复保护和发送前核验仍由已有后台控制。

### F2：按分钟保存额度采样，并提供最近24小时数据

原来没有额度采样表和折线图；现在增加SQLite表 `quota_samples`，以账户散列和分钟时间戳作为主键。每次成功发布额度快照时采样；同一分钟保留检测完成时间较新的读数。周额度缺失时保存为空，不填成0。`quota_history`只返回当前账户最近24小时且不晚于查询时间的采样；页面再筛选一小时、五小时或二十四小时。

```text
分钟 = 向下取整(检测完成时间 / 60) × 60
键 = (当前账户散列, 分钟)
如果该键没有数据，或本次完成时间不早于已有数据：
    写入五小时使用比例、周使用比例（可能为空）、完成时间
展示值 = 100 - 使用比例
断网、休眠或暂停且未检测的分钟没有采样，不补造历史
```

统计复用额度读取结果，不为绘图额外发送模型请求。采样随月度日志保留处理，清理早于保留月份起点的采样；“返回最近24小时”与“磁盘仅保存24小时”是不同概念，代码并未实施后者。

### F3：统计选框长期记忆

新增的统计时间范围及额度类型保存在当前浏览器的 `localStorage`；刷新、关闭和重新打开页面后恢复。无效选项回退到默认选项；存储不可用或抛异常时，页面继续运行。此设置属于浏览器，不是后台SQLite中的全局偏好。

### F4：暂停后是否继续检测可配置

原来暂停发送仍继续读取额度；现在新增 `pollWhilePaused` 布尔设置，默认 `false`，由SQLite状态保存。正常轮询、`nextPoll`显示和后台唤醒均使用同一暂停检测条件。暂停且该开关关闭时不进行自动额度读取；开启时继续只读检测和采样，仍不发送小额请求。手动“重新检测”“重新连接”不受该开关阻止。

```text
允许自动检测 = 未暂停发送 或 pollWhilePaused
后台到达原定检测时间且允许自动检测：执行原有检测
手动只读操作：仍可执行
暂停发送：始终禁止后台小额请求
```

页面标签为“关闭软件后依然每分钟检测额度变化”，但代码实际控制的是暂停期间检测。关闭网页不等于退出后台；后台退出、电脑休眠或关机后不能继续检测。“每分钟”指每轮结束后再等待60秒，不保证每个自然分钟都产生采样。

### F5：月度日志保留与旧文件迁移

基准版本已经把事件写入 `data/logs/quota-starter-YYYY-MM.jsonl`，页面操作日志也已经排除例行 `check` 事件；这两点不是远程相对1.5.23新增的功能。远程保留统一事件归档，并新增保留期限、采样清理及旧触发文件迁移。中间版本曾单独输出触发归档，但这不是基准版本的行为，最终远程也不再单独输出。

按北京时间，仅保留本月、上月、上上月对应的活动归档。跨月后的第一次归档处理执行清理；错过月初会补做。只匹配软件规定的月度文件名，失败则保留游标和重试条件。

保留月份范围内的旧 `triggers/quota-triggers-YYYY-MM.jsonl` 按事件编号合并；相同整数编号且权威字段一致时去重，编号冲突或格式无效时不删除源文件。缺少整数编号的记录按原始文本作为去重键。先在 `legacy-archive-backups` 写入并核验带源文件SHA-256前12位的 `.bak`，再原子替换统一JSONL，最后移除旧活动JSONL。早于保留月份的旧触发JSONL直接按保留规则删除，不走合并和备份；`.bak`不属于活动月度JSONL清理规则。

```text
如果旧文件早于保留月份：按保留规则删除，不进入下面的合并分支
校验旧触发归档的所有记录
如果编号冲突或格式无效：保留原文件，报告归档错误，等待下次重试
否则：合并去重 → 保存并校验旧原字节.bak → 原子替换统一归档 → 移除旧JSONL
```

### F6：小额请求结果说明与日志合并

原来的独立触发记录列表被移除；最终远程UI只在“日志”中合并展示小额请求结果、周期证据和待核实请求。后台保留 `trigger_history` 兼容数据及对应接口路径，不等于界面仍有独立触发卡片。

基准的操作日志原本已经显示有对应trigger事件的完成结果和周期证据；远程新增的是 `Store.activity` 从attempts表补入没有对应trigger事件的请求，并按attempt编号去重。这样，崩溃前已预留但未写最终事件的请求也可进入合并日志，不能把全部请求结果展示都说成首次新增。

请求完成且前后五小时刷新时间相差不超过5秒时，明确说明刷新时间未变。请求已完成、原刷新时间不晚于发送起点、且新刷新时间接近发送起点加五小时（误差不超过120秒）时，说明观察到五小时倒计时。其他情况保留证据不足或核验失败的说明；并非证明短请求必然决定服务器周期起点。

上述两个数值判定条件在两版中相同；净变化是两条提示文案改为明确说明“小额请求未改变刷新时间”或“将于五小时后刷新”，不是新增一套周期验证算法。

### F7：本地网页端口统一

默认网页服务、启动脚本中的探活和打开地址、诊断地址从8769改为8770。`create_server`仍接受显式端口参数。该变化属于本地网页服务，不是Codex CLI协议或远端接口地址变化。

### F8：错误横幅

原来没有标题下方的错误横幅；现在展示当前连接错误、CLI不兼容、自启错误或当前操作错误，恢复后隐藏。历史日志中的旧错误不会单独使横幅重新出现。错误字符串通过 `textContent` 写入，不作为HTML解析。连接相关错误的产生与处理条件另见并列的“Codex CLI 连接”章节。

### 首屏高度的准确条件

固定远程提交的 `fitChartCard` 用 `统计卡顶部文档坐标 = getBoundingClientRect().top + scrollY`，计算 `剩余高度 = innerHeight - 顶部文档坐标 - 20px留白`。**只有视口宽度大于1000px且剩余高度至少140px时**才写入统计卡高度；其余情况清除内联高度，退回内容高度。因此，不能将该远程实现描述为“任意窗口下始终恰好100vh”。宽度不超过1000px时，上方两卡还会按原媒体查询改为上下排列。

这一限制在本次独立预览中复现：旧远程页面在1280×600可视区下，统计卡底部加20px留白达到约758.33px；在1000×1080可视区下达到约1113.67px。这是远程已有布局条件的结果，不是连接机制问题。本次1.7.1对统计卡适配条件的修正另记在当前CHANGELOG，不混入本报告的历史差异。

      function chartScale(points) {
        const values = points.map((p) => p.value),
          min = values.length ? Math.min(...values) : 0,
          max = values.length ? Math.max(...values) : 100;
        const span = Math.max(20, max - min + 6),

          high = Math.min(100, Math.ceil((max + 3) / step) * step);
        if (high - low < 20) {

      function chartSegments(points, x, y) {
        const segments = [];
        // Monotone Hermite interpolation passes through every measurement. Opposing
        // slopes flatten at the sample, so smoothing cannot invent overshoot or hide drops.
        const slope = (a, b) => (b.value - a.value) / (b.minute - a.minute);
        const tangent = (i) => {
          const a = points[i - 1],
            b = points[i],
            c = points[i + 1];
          const before = a && b.minute - a.minute === 60 ? slope(a, b) : null,
            after = c && c.minute - b.minute === 60 ? slope(b, c) : null;
          if (before === null) return after || 0;
          if (after === null) return before;
          return before * after <= 0
            ? 0
            : (2 * before * after) / (before + after);
        };
        for (let i = 1; i < points.length; i++) {
          const a = points[i - 1],
            b = points[i];
          if (b.minute - a.minute !== 60) continue;
          const h = (b.minute - a.minute) / 3,
            ax = x(a.minute),
            bx = x(b.minute);
          segments.push({
            d: `M${ax} ${y(a.value)} C${ax + (bx - ax) / 3} ${y(a.value + tangent(i - 1) * h)},${bx - (bx - ax) / 3} ${y(b.value - tangent(i) * h)},${bx} ${y(b.value)}`,
          });
        }
        return segments;
      }

## Codex CLI 连接

本节仅记录v1.5.23到固定远程提交之间已经存在的连接差异。本次1.7.1不调整这些机制，不实施指数退避。

### C1：CLI查找顺序

原来在显式 `QUOTA_CODEX_EXE` 之后先查PATH中的 `codex.exe`，再查npm目录；远程改为先查npm安装位置和shim推导目录，之后才回退到PATH中的 `codex.exe`。显式覆盖仍优先，并仍要求现有官方 `.exe` 文件。该变化影响选用哪一个CLI，不会自动安装或升级CLI。

### C2：子进程代理环境与启动参数

新增 `configure_proxy`，优先 `QUOTA_HTTP_PROXY`，其次Windows系统代理；没有这两者时保留环境变量代理。选用显式或系统代理时清理旧HTTP/HTTPS/ALL_PROXY变量并写入选中的HTTP/HTTPS代理，合并本机 `NO_PROXY` 地址。代理诊断只记录路由来源和不含认证信息的代理地址。

启动参数由 `features.respect_system_proxy=true` 改为 `false`；已解析到明确代理时再设置 `features.system_proxy_fallback=false`。代理配置只传给新建的Codex子进程，不写用户全局CLI或系统代理配置；正在复用的既有子进程不会因每次额度读取自动重新创建。

### C3：额度接口不兼容识别与提示

新增 `CodexCompatibilityError`。当 `account/rateLimits/read` 返回方法不存在，或特定无效请求/参数错误包含 `expected unit` / `excludeResetCreditDetails` 时，转为兼容错误；调用同一个CLI的 `--version`，在当前预算内最多等待3秒，提示版本、实际路径和升级命令。此类错误停止无效重试；不按未经验证的最低版本数字猜测兼容性。

两个提交的额度读取调用均使用 `excludeResetCreditDetails`；该参数不是此次历史对比中新加的参数。新增的是对拒绝该接口/参数的响应进行识别和说明。

### C4：只读HTTP临时错误分类与连接复用

在能确认是账户/额度只读方法时，HTTP 408、425、429、500、502、503、504 被识别为临时错误。401、403等永久HTTP状态优先停止，不因错误文本包含网络词语而误入恢复。

原来失败后关闭连接；远程在可恢复、非本地TimeoutError/ConnectionError、诊断方法为账户或额度读取、且子进程仍存活时保留同一传输供本轮重试使用。进程退出、本地超时或整轮耗尽等情况仍关闭；发送结果未知继续停止保护。失败诊断新增传输信息和 `reusedTransport`，兼容错误附原始服务端错误。

### C5：恢复记录与保留的重试规则

手动重连成功也记录 `connection_recovered`。连接短时重试仍为最多5次（含首次）、间隔10秒、总预算60秒；网络故障耗尽后仍每20分钟单次尝试恢复，每次预算60秒，不叠加快速重试。正常完成后的检测间隔仍为60秒。本报告不把这些保留规则写成新增的指数退避机制。
