# 额度启程 · Quota Starter

一个在 Windows 后台运行的小工具：读取 **ChatGPT Plus 的 Work / Codex 共享额度**，在服务器报告的五小时窗口结束后，尽快通过官方 Codex CLI 发送一条最小请求，并记录结果。

**它已经能真实发送订阅内的 Codex 请求，不只是提醒器。但它不能保证改变服务器的额度算法，也不能声称已经验证了“提前发送就一定提前开始下一轮五小时”。**

当前版本：`v1.0.0`。Python 3.11+，没有第三方 Python 依赖。已在 Windows 与官方 Codex CLI `0.144.4` 上验证。

## 你最关心的：它究竟有什么用？

假设服务器给出的下一次重置时间是 19:38：

1. 工具持续读取真实额度，正常情况下每 60 秒检查一次，临近边界按服务器时间提前安排下一次检查。
2. 到 19:38 后加约 2 秒缓冲，再读取额度；只要服务器仍允许普通订阅使用，就尝试提交一次 `Reply OK.`。
3. 使用实际目录中可用的轻量模型，当前机器选择 `gpt-6-luna`、`low` 推理和标准速度。
4. 收到服务器的完成事件后，记录回复、token 用量，以及请求前后的重置时间。
5. 如果新时间约等于发送时间加 5 小时，记录为“支持首次请求锚定的观察证据”；如果时间没变，则明确写“不能证明启动了新周期”。

如果你已经在新窗口正常使用了 Work / Codex，且服务器显示已有使用，工具通常会跳过额外请求，因为窗口已经有实际活动。首次启动时如果服务器显示用量为 0，也可以尝试启动一次；0% 可能经过取整，并不等于精确的零消耗。

**不会突破五小时额度或每周额度，不会增加总配额，不会购买积分，也不会使用账户中赠送的额度重置券。**

## 已确认什么，尚未确认什么？

| 项目 | 当前结论 |
| --- | --- |
| Work 与 Codex 是否共用额度 | 官方文档明确确认 |
| 这台电脑是否能直接读到额度 | 可以；真实 Plus 账户返回 `codex` 桶、300 分钟窗口和 10080 分钟长周期 |
| 是否使用普通 Chat 或 API Key 额度 | 否；只接受 ChatGPT Plus 登录，使用 Codex 官方提供方，拒绝 API Key 登录 |
| 是否能完成真实请求 | 可以；实测轻量模型返回 `OK`，状态为 `completed`，同时收到 `codex` 额度事件 |
| 现有窗口内发送请求会不会让重置时间重新延后五小时 | 本次实测没有改变原重置时间 |
| 刷新后第一个请求是否决定下一窗口起点 | **尚未完成跨自然重置边界的实测，公开资料也没有给出精确算法** |
| 是否保证精确在重置瞬间发送 | 不保证；网络、服务器返回、Windows 调度、睡眠与关机都可能产生延迟 |

进一步的调查过程、官方链接和推断边界见 [机制调查](MECHANISM.md)。不要把“请求完成”与“预期额度收益已经证实”当成同一件事。

## 打开与日常使用

安装后，双击桌面的 **Quota Starter** 快捷方式，或在 Windows 开始菜单搜索 **Quota Starter**，也可以打开：

**[http://127.0.0.1:8769](http://127.0.0.1:8769)**

页面显示：

- 五小时剩余百分比、长周期剩余百分比。
- 服务器报告的下次重置时间与倒计时，统一显示北京时间。
- 上次检测时间、下次检测时间、上次提交尝试。
- 请求是否完成，以及当前能得出的周期机制结论。
- 最近的触发记录、检测和错误日志。

三个按钮：

| 按钮 | 行为 |
| --- | --- |
| 手动触发一次 | 现在尝试最小请求，仍然遵守额度检查和周期去重；不能靠连点重复发送 |
| 暂停 / 恢复运行 | 暂停后继续显示额度，但不再提交新的自动或手动请求；已提交的请求可能仍会完成。暂停状态重启后保留 |
| 立即检测 | 重新安排一次额度检测；处于运行状态且满足触发条件时，检测也会触发一次请求 |

页面下方“设置”提供 **开机自启动（登录 Windows 后）** 开关：修改后会直接开启/禁用 Windows 计划任务，并显示实际状态。关闭自启不会停止当前服务；需要停止发送时另点“暂停”。

关闭页面不会关闭后台程序。不必把浏览器保持在前台，也不必保持 Codex 桌面窗口打开。

## 安装

### 这次交付的电脑

已安装到固定目录 `%LOCALAPPDATA%\Programs\QuotaStarter`，具体安装与验证结果见 [验收记录](VALIDATION.md)。不用再次安装，不需要提供密码或导出凭据。

### 在另一台 Windows 电脑上安装

1. 安装 Python 3.11 或更高版本，并让 `python` 命令可用。
2. 安装官方 Codex CLI：`npm install -g @openai/codex`。该安装步骤需要 Node.js/npm。
3. 运行 `codex login`，在官方登录页面使用你的 ChatGPT Plus 账户登录。已经登录过就跳过。
4. 下载 Release 的 ZIP 并完整解压，双击 `Install.cmd`。

安装器复制程序到 `%LOCALAPPDATA%\Programs\QuotaStarter`，添加桌面快捷方式和开始菜单入口，并注册 `QuotaStarter-WorkCodex` 计划任务。整个过程使用当前 Windows 用户；不要求账户密码。受企业策略限制而无法注册计划任务时，安装器会报错，不会假称自启已成功。

**“自启”指开机后登录当前 Windows 用户时启动**，不是在无人登录的系统启动阶段运行。用户保持登录而锁屏时仍可运行；休眠、关机、断网时无法发送，恢复后重新读取服务器状态。

只想运行解压版，可双击 `Start.cmd`。请不要同时运行多个副本；固定本地端口、进程锁和持久化记录会阻止常见重复启动，但不同数据目录、另一台电脑无法共享本机去重账本。

## 停止、卸载与升级

- 暂时不发送：在页面点“暂停”。这是最方便的日常开关。
- 完全停止本次后台运行：右键安装目录内的 `Stop.ps1`，用 PowerShell 运行。下次登录仍会自动启动。
- 取消自启并停止后台：运行 `Uninstall-Autostart.ps1`。
- 卸载运行集成：运行 `Uninstall.ps1`，移除自启、桌面快捷方式和开始菜单入口；程序文件与记录保留，确认不再需要后自行删除安装目录。
- 升级：解压新版并运行新版 `Install.cmd`。安装器保留已有 `data` 目录和防重复记录，不覆盖你的状态数据库。

PowerShell 直接执行脚本被系统执行策略拦住时，可在终端使用 `powershell -NoProfile -ExecutionPolicy Bypass -File .\脚本名.ps1`。这只影响本次进程，不修改系统全局策略。

## 避免重复消耗是怎么做的？

发送前，工具在 SQLite 事务里写入“本周期已预留”的记录，然后才调用 `turn/start`。多次点击、服务崩溃和重启都不能简单地再次发送同一请求。

网络系统无法仅凭客户端实现“绝不漏发且绝不重复”的严格 exactly-once。本工具选择 **at-most-once（宁可漏一次，也不盲目重复）**：

- 请求结果未知、超时或进程意外退出时，保留预留记录，不自动重试该提交。
- 结果未知时，另设约五小时加两分钟的保护时间，避免服务器时间变化导致立即重复。
- 成功后按服务器返回的新窗口关联去重记录。
- 检测接口失败会退避重连；提交接口结果未知不会自动重放。
- 同一本地安装的不同登录标识共用防重复保护；接口偶尔不返回账户 ID、升级迁移或切换登录不会绕过已有保护。切换账户时可能保守等待前一账户保护期结束。
- 额度字段缺失、目标桶不明、不是 Plus、每周已用尽或服务器明确限制时，停止发送。

如果界面显示“已预留 / 待核实”，表示程序可能在提交前后中断；它不是完成记录。**不要为了重试删除 `data`，这会破坏去重依据。**

## 请求开销

提示词很短，模型回复限制为 `OK`；空白临时线程不会累积历史。程序关闭自己的插件、记忆、hooks、用户 MCP、Shell 与多代理功能，限制技能目录上下文，并采用标准速度。

但官方 Codex 运行时仍可能添加系统指令和工具描述，所以不是“两个字符就只消耗两个 token”。首次完整链路实测在进一步精简配置前共使用 15622 token；精简配置下的一次实测为 6746 token，约降低 57%。这些只是本机特定版本的观察值，不是固定价格或每次用量承诺。第二次请求来自安装迁移回归时发现的身份兼容缺陷，已修复并加入测试；没有隐藏该记录。实际用量会逐次保存在本机记录中。官方按模型及任务计量，不能用 token 数直接推导额度百分比。

## 故障排查

| 现象 | 处理 |
| --- | --- |
| 页面打不开 | 从开始菜单重新打开；检查 `data\supervisor.log`；确认端口 8769 没被其他程序占用 |
| 提示不是 ChatGPT Plus 登录 | 运行 `codex login status`；使用官方 `codex login` 恢复正确登录 |
| 无法获取额度 | 检查网络与官方服务；程序会自动退避重试，不靠本地推算发送 |
| 已到重置时间仍未发送 | 查看每周额度、暂停状态和去重记录；如果服务器仍报告用量 100%，工具等待其恢复，避免落到付费积分 |
| 轻量模型不可用 | 程序停止发送；不会自动切到高消耗模型。升级 CLI 后再检查 |
| 自启后没有运行 | 在任务计划程序检查 `QuotaStarter-WorkCodex`；确认 Python 路径没有被删除或移动 |
| 更新系统或 CLI 后报错 | App Server 协议可能变化；保留数据，运行诊断并查看错误，勿删除登录凭据 |

只读诊断：`python -X utf8 diagnose.py`。

显式真实请求诊断：`python -X utf8 diagnose.py --send-once`。同样遵守现有暂停、额度与去重记录。

## 数据与隐私

运行记录只写入安装目录下的 `data\quota.sqlite3`，包含时间、额度快照、请求状态、回复、token 用量、线程编号和账户标识的哈希。日志保留最近约 60000 条检测事件；触发记录长期保留。

程序不读取、复制、导出或上传 `auth.json`，由官方 CLI 管理登录。它会读取本机 `config.toml` 中的 MCP 名称，以便仅为自己的进程关闭这些集成，不修改原文件。本地界面只监听 `127.0.0.1`，写操作校验来源和随机令牌；不会监听局域网地址。

**公开 GitHub 仓库和 Release 均不包含运行数据库、登录凭据或本机账号资料。** 提交问题时请先检查自己附加的日志是否包含你不想公开的信息。

## 开发与验证

```powershell
python -X utf8 -m unittest -v test_quota
python -X utf8 build_release.py
```

测试使用模拟额度和本地 HTTP，不消耗 ChatGPT 配额。覆盖跨边界、重复点击、并发占位、超时后重启、账户切换、每周耗尽、未知字段、暂停恢复、HTTP 来源校验等。GitHub Actions 在 Windows 上运行相同测试。

主要文件：`rpc.py` 负责官方协议，`core.py` 负责调度与去重，`app.py` / `ui.html` 提供本地界面，`supervisor.py` 负责异常重启，PowerShell 脚本负责安装、自启和卸载。
