# 额度启程 · Quota Starter

当前版本：1.7.0

Quota Starter 是一个 Windows 后台工具，用于查看 ChatGPT Plus 的 Work / Codex 共享额度，并在额度刷新后尝试发送一次简短请求。你也可以选择希望的刷新时间，由软件提前五小时安排请求。

软件提供中文本地网页界面，支持自动检测、定时刷新、暂停运行和登录自启。关闭网页后，后台仍会继续运行。

## 安装

### 1. 准备运行环境

需要 Windows、Python 3.11 或更高版本，以及官方 Codex CLI。安装程序不会自动安装这些依赖。

1. 从 [Python 官网](https://www.python.org/downloads/windows/) 安装 Python，安装时勾选 **Add python.exe to PATH**。
2. 从 [Node.js 官网](https://nodejs.org/) 安装 LTS 版本，它包含 npm。
3. 打开 PowerShell，依次运行：

   ```powershell
   npm install -g @openai/codex
   codex login
   ```

4. 按浏览器提示，使用你的 **ChatGPT Plus 账户**完成登录。已有上述环境且已登录的用户可直接下载安装包。

软件优先使用通过 npm 安装的 Codex CLI，避免桌面应用注入 PATH 的预览版抢先被选中；`QUOTA_CODEX_EXE` 可显式指定官方 `codex.exe`。启动和每次重连前读取当前启用的 Windows 系统代理，将其明确传给子进程；本机配置为 `127.0.0.1:7897` 时从首次请求起使用该代理，不写死端口。`QUOTA_HTTP_PROXY` 可显式覆盖；没有系统代理时沿用已有代理环境变量。代理只作用于软件启动的子进程，不修改全局设置。

若提示“Codex CLI 版本过低或接口不兼容”，在 PowerShell 运行 `npm install -g @openai/codex@latest`，完成后点击“重新连接”。提示包含实际调用的 CLI 版本和路径；更新额度软件不会自动更新 CLI。软件按接口是否支持所需参数判断兼容性，不限定未经验证的最低版本号。

### 2. 下载并安装

1. 打开 [最新版下载页](https://github.com/Symplatt/codex-quota-starter/releases/latest)。
2. 在 **Assets** 中下载 `quota-starter-版本号-windows.zip`，不要选择 `Source code`。
3. 右键 ZIP，选择 **全部解压**。
4. 打开解压后的 `quota-starter` 文件夹，双击 **Install.cmd**，等待安装完成。不要直接从压缩包窗口运行。
5. 双击桌面或开始菜单中的 **Quota Starter**，打开软件界面。

默认安装位置为 `%LOCALAPPDATA%\Programs\QuotaStarter`，安装后会在登录当前 Windows 用户时自动启动。当前使用脚本安装，没有 EXE 安装向导。仅解压文件不代表已安装成功；安装报错时请保留窗口中的错误信息。

### 从旧版本升级

下载新版 Windows ZIP，完整解压后运行新版 **Install.cmd** 即可覆盖安装，无需先卸载。安装会刷新程序缓存，已有历史记录、时间计划、暂停状态和自启设置会保留。

## 开始使用

页面标题下方仅在发生错误时显示横幅，列出连接、CLI 兼容性、自启或操作错误；连接恢复或相应操作成功后自动隐藏，不显示历史错误。CLI 接口不兼容时立即停止重试，升级后手动重新连接。

通过 **Quota Starter** 快捷方式打开界面；后台运行时也可访问 [本地页面](http://127.0.0.1:8770)。主页保留“定时刷新”和“运行状态”两张等宽卡片，日期与时间按北京时间显示。标题右侧的操作控件垂直居中；卡片横向、纵向间隔统一为20像素。页面和日志使用细滚动条。

“日志”卡片汇总最近50条操作、连接及小额请求记录，包括计划的原/新时间、手动检测、重连、暂停、自启、连接故障与恢复，以及小额请求的结果和周期验证；未完成的预留请求也会显示。每分钟定时额度读取不进入此列表。日志卡片高度加上下各20像素留白恰好占满网页可视区域，点击“日志”标题平滑定位到完整卡片，三列首行文字顶端对齐，记录在卡片内独立滚动；完整月度统一日志通过标题右侧按钮打开。正式版默认固定使用8770端口；桌面快捷方式、登录自启及诊断均连接同一个后台。正常连接运行时显示“后台运行”，暂停时显示“停止运行”。

正常连接时，每轮检测或发送结束后等待60秒再自动检测，临近或越过刷新时间也不加快频率。手动“重新检测”和“重新连接”立即执行，成功后恢复60秒间隔；失败重试仍间隔10秒。已返回的临时网络错误先复用一次仍正常的连接，避免反复进行冷启动路由发现；再次失败、进程退出或本地 RPC 超时则重建连接。每轮仍最多5次、总计60秒，耗尽后保持原有每20分钟恢复一次的规则。时间计划在到点后的下一轮自动检测中处理，保存或取消计划不会额外触发检测。如果当前窗口已经有实际使用，软件通常跳过额外请求；暂停状态下需要点击 **恢复运行** 才会继续发送。

| 操作 | 用途 |
| --- | --- |
| 选择时间 | 设置希望的刷新时间，软件自动提前五小时安排请求 |
| 恢复自动 | 取消手动计划，重新按服务器报告的刷新定时刷新；没有待执行的手动计划时按钮灰淡且不可点击 |
| 重新检测 | 只重新读取当前额度和服务器刷新时间，不发送小额请求，不提前执行时间计划；暂停时也可使用 |
| 重新连接 | 清除连接重试计数，先连接并读取额度，再交回后台调度；网络故障会自动重连，也可手动立即重连；暂停设置与发送记录保留 |
| 暂停 / 恢复运行 | 暂停发送，默认同时停止自动检测额度；恢复后继续调度，已提交的请求可能继续完成 |
| 关闭软件后依然每分钟检测额度变化 | 默认关闭；开启后，暂停期间仍在每轮完成60秒后只读检测额度并更新折线图，不发送小额请求 |
| 开机自启动 | 在页面下方设置登录 Windows 后是否启动；关闭此开关不会停止当前后台 |

定时刷新与运行状态卡片统一在标题右侧显示操作按钮；标题字号较大，窄窗口自动将按钮换到标题下方。并排时卡片等高，底部分隔线对齐。两张卡片的五个操作采用无底色、无常驻边框的文字按钮，悬停时显示下划线；运行状态按钮从左到右为“重新检测”、“重新连接”和“暂停 / 恢复运行”。定时刷新使用固定长度的横向时间轴，上方显示额度刷新与预计再次刷新，下方显示发送请求，每个事件保留北京时间和日期；等待超过五小时时以断轴符号省略部分距离，短间隔按比例显示，相邻事件保留最小可见间距。时间轴三个事件采用统一信息块，首个额度刷新节点卡与“定时刷新”标题左对齐，发送请求节点通过竖线连接信息卡，两端延伸刻度范围，刷新节点向内收，留出左右余量。时间轴带尺子式长短刻度，整点用灰色小字标注；断轴省略中间时段，窄窗口自动减少整点标注以避免重叠。两张卡片等宽等高；运行状态并列显示上次和下次检测时间，悬停时可查看完整日期；底部保留简要状态，鼠标悬停可查看完整原因，操作结果显示在页面右下方，成功提示3.5秒后关闭，错误提示7秒后关闭。窄窗口自动上下排列，并按内容收紧卡片高度。

“重新检测”、“重新连接”、“暂停 / 恢复运行”的可用文字为灰绿色；不可用时仍灰淡显示。

小额请求的状态、原因和周期验证统一显示在日志中。请求前后刷新时间相差不超过5秒时说明刷新时间未变；请求完成、原刷新时间已过且服务器返回约五小时倒计时时说明已进入五小时倒计时。其他变化或核验失败按实际结果显示，历史原始证据保留。额度检测、操作、连接及小额请求共同写入每月同一份 JSONL 文件；页面隐藏的每分钟额度检测仍完整写入文件。旧触发归档按事件编号去重合并，原档逐字节备份为 `.bak` 后移除旧 JSONL，格式无效或编号冲突时保留原文件并重试。

设置中的“关闭软件后依然每分钟检测额度变化”控制点击“暂停”后的检测；关闭网页不等于暂停或退出后台，后台进程退出、电脑休眠或关机后无法继续检测。默认关闭时，暂停期间不产生自动额度请求和新采样点，折线图保留已有数据；手动重新检测和重新连接仍然可用。该设置保存到本机，重启后保留。

### 设置刷新时间

点击 **选择时间**，窗口提示“选择**完成刷新**的时间”。输入年、月、日、时、分，或滚动各列选择数值（滚轮响应间隔由90毫秒缩短至30毫秒），然后点击 **确定**。秒固定为 `00`。取消、按 Esc 或点击弹窗外侧不会保存。

例如，选择 10 月 11 日 12:00 刷新，会安排 10 月 11 日 07:00 发送请求。主页时间轴显示服务器额度刷新、请求发送和预计再次刷新的时间。

“发送请求”的圆点始终保持不透明墨绿色，检测或连接中不能拖动时也不褪色。也可左右拖动该圆点，以十分钟为一格调整发送时间，预计刷新时间同步保持在发送后五小时，松开保存。原时间为03:33时，首次向左吸附至03:30，向右吸附至03:40；方向键左右也可调整，取消拖动不保存。弹窗仍支持任意整分钟。拖动遵守相同可选范围，正在检测或保存时不可拖动。

不可用时间会灰置：推算出的发送时间须晚于当前时间和最近检测到的服务器刷新时间，且不早于防重复保护结束时间，并在未来 366 天内。未检测到服务器刷新时间时，选择按钮不可用。

待执行的手动计划优先于额度恢复后的自动发送。额度恢复且五小时使用量为0%时，即使服务器刷新时间滚动到五小时后，仍保留计划并等待设定的发送时间；例如03:00恢复、计划03:30发送，不会在03:00后提前发送。

每次定时检测、重新检测、重新连接及发送前校验都会检查计划：仅当五小时窗口已有使用，且服务器刷新时间达到或超过计划发送时间时，自动取消该任务，恢复自动安排并记录取消原因。启动时按同一规则检查已有快照；缺少使用量的旧快照保留计划，待连接后核验。

到点发送仍须满足额度、暂停状态及防重复条件。睡眠、关机或断网可能造成延迟；预计刷新时间按发送时间加五小时计算，实际刷新以服务器返回为准。

### 额度变化统计

统计卡占据整个内容区，位于两张概览卡片下方、日志上方；以电脑浏览器网页可视高度（不含浏览器工具栏和系统任务栏）动态调整统计卡：软件标题、上方两张卡片、统计卡及其下方20像素间隔合计恰好占满100vh，日志从下一屏开始；上方两张卡片布局不变。细折线显示每分钟剩余额度；可切换五小时或周额度，以及最近一小时、五小时、二十四小时。横轴细刻度随范围变化，纵轴根据当前数据取值调整范围并增加刻度密度；曲线穿过每个真实采样点，平滑连接不产生超出采样的峰谷，曲线始终为墨绿色，快速消耗直接体现为陡降，不显示图例或变色，缺测不连线。标题与图表之间保留24像素留白；悬浮标签固定两行，第一行是日期时间，第二行是剩余额度和分钟变化，消耗和恢复的百分点按整数显示。两个选框会在当前浏览器中长期保存上次选择，刷新或重新打开页面时自动恢复。

统计复用现有检测，不额外发送模型请求；同一分钟以最后一次读取为准，关闭网页或重启后台保留采样。休眠、断网或未检测的分钟留空，跨缺口不计算变化；只显示当前账户的采样，升级前未采样的历史不补造。变化按服务器返回的百分比计算，单位为百分点，不代表精确 Token 数；检测仍在每轮完成后间隔60秒。

## 运行条件与请求开销

软件使用已登录的官方 Codex CLI 读取额度并发送简短请求，不使用 API Key。发送会消耗订阅内额度，实际开销以记录为准；短提示词仍可能包含官方运行时添加的上下文。

软件不会增加总配额、突破五小时或每周限制、购买积分或使用额度重置券。额度不足、登录不符合要求或额度信息无法确认时，不会发送。

请求已能实际完成，但“刷新后的首次请求是否决定下一轮五小时起点”尚未完成跨自然刷新边界的验证，因此不能保证按所选时间刷新。机制依据见 [机制说明](MECHANISM.md)，已有测试见 [验证记录](VALIDATION.md)。

自动运行需要电脑开机并登录当前 Windows 用户。锁屏时可继续运行；休眠、关机或断网时无法发送。无需一直打开网页或 Codex 桌面窗口。

每轮连接、检测或发送最多尝试5次（含首次），失败后间隔10秒，从首次尝试起最多1分钟。检测遇到临时网络故障时，短时重试达到上限后，每20分钟自动尝试一次恢复连接（每小时三次），每次最多等待60秒，失败后不再叠加五次快速重试；重启保留等待时间，休眠错过的尝试不补跑。恢复后先只读取额度，60秒后的下一轮检测再处理仍有效的到期计划。身份、额度数据等非网络错误，以及结果未知的发送达到重试上限时仍停止，须点击“重新连接”。小额请求重试前重新检查额度，结果未知的重试可能产生额外用量；每轮发送记录保留，手动重连不清除周期防重复记录。暂停会停止等待中的发送重试。

连接完成后即更新额度，另行显示准备、发送及核验请求的状态。重新检测在后台执行，不等待小额请求完成；自启动状态查询不会阻塞额度显示。

软件为自己的 Codex 子进程启用系统代理跟随，不修改电脑或 Codex 全局配置；账户或额度读取发生网络故障后，下一次短时重试会重建子进程，重新取得网络路由。额度读取不再额外查询重置券详情。请求已确认成功后，后续额度核验超时仍按可恢复的连接故障处理，不误判为发送结果未知。

软件信息显示名称、版本及版权声明“版权所有 © 2026 Symplatt”。

## 停止与卸载

- **暂时停止发送**：在页面点击“暂停”，状态在重启后保留。
- **停止当前后台**：运行安装目录的 `Stop.ps1`；自启开启时，下次登录仍会启动。
- **取消自启并停止后台**：运行 `Uninstall-Autostart.ps1`。
- **卸载**：运行 `Uninstall.ps1`，移除自启及快捷方式。程序文件与数据会保留，需要彻底删除时，再自行删除安装目录。

将 `%LOCALAPPDATA%\Programs\QuotaStarter` 粘贴到文件资源管理器地址栏即可打开安装目录。右键所需 `.ps1` 文件，选择“使用 PowerShell 运行”。执行策略阻止脚本时，可在该目录打开 PowerShell，运行以下命令，将文件名替换为所需脚本：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Stop.ps1
```

该命令只影响当前进程，不修改系统全局执行策略。

## 常见问题

| 问题 | 处理方法 |
| --- | --- |
| 安装提示找不到 Python 或 Codex | 检查依赖安装，重新打开 PowerShell，执行 `python --version` 和 `codex --version` |
| 页面打不开 | 从快捷方式重新启动，检查安装目录的 `data\supervisor.log`；确认本地端口 8770 未被占用 |
| 提示不是 ChatGPT Plus 登录 | 用 `codex login status` 检查登录，运行 `codex login` 登录 Plus 账户 |
| 无法获取额度 | 检查网络与官方服务；网络故障后每20分钟自动重连一次，也可点击“重新连接”立即重试 |
| 到点仍未发送 | 检查暂停状态、每周额度和防重复记录；服务器仍报告额度用尽时会继续等待 |
| 提示轻量模型不可用 | 更新官方 Codex CLI 后重新检测；软件不会自动切换到高消耗模型 |
| 登录后没有自启 | 检查页面自启开关和 Windows 任务计划程序中的 `QuotaStarter-WorkCodex`；确认 Python 未被移动或删除 |
| 无法设置自启 | 检查是否受 Windows 或企业策略限制，保留安装错误信息 |

进一步诊断：在安装目录打开 PowerShell，运行 `python -X utf8 diagnose.py`，该命令不发送请求。提交问题前请检查日志，移除不希望公开的信息。

## 数据与隐私

统计选框偏好保存在当前浏览器的本机站点存储（localStorage）。其余配置及运行记录保存在安装目录的 `data` 中，数据库为 `quota.sqlite3`，记录额度快照、请求状态、时间、回复、用量及账户标识的哈希。覆盖升级保留此目录。

登录由官方 Codex CLI 管理，软件不复制或上传登录凭据。它读取本机 Codex 配置中的 MCP 名称，为自己的运行进程关闭相关集成，不修改原配置。本地页面只监听本机地址 `127.0.0.1`。

公开仓库和安装包不包含本机数据库或账号资料。

### 统一 JSONL 日志

点击“日志”卡片右上角“打开日志文件夹”，打开 `%LOCALAPPDATA%\Programs\QuotaStarter\data\logs`。额度检测、操作、连接、小额请求结果及周期验证统一写入按北京时间月份保存的 `quota-starter-YYYY-MM.jsonl`，每行一条完整事件。页面不显示的每分钟自动检测也照常写入；页面最近50条限制不影响文件归档。

升级时把旧 `data\triggers\quota-triggers-YYYY-MM.jsonl` 合并到同月统一日志，按事件编号去重，并保留旧档的扩展证据。原文件校验备份到 `data\legacy-archive-backups`（`.bak`）后删除旧 JSONL；异常文件保留并重试，不覆盖证据或丢弃数据。无关文件不动。旧 `/api/triggers/open` 接口兼容打开统一日志目录。

月度日志按北京时间只保留本月、上月和上上月，每月1日清理更早文件；月初未运行时，下次启动或写入补清理，失败自动重试。数据库先保存完整事件，再同步归档。异常断电发生在写入与进度保存之间时，普通追加可能出现相同事件 ID 的重复行。使用自定义 `--data` 时保存在该目录的 `logs` 下。

定时刷新与运行状态采用等宽卡片，卡片间距20像素，卡片左右内边距与“日志”卡片一致，均为24像素，时间轴上的三个时间小卡等宽、最大190像素；运行状态以环形进度显示“五小时额度”和“周额度”，并并列显示上次、下次检测时间。顶部操作使用独立竖线分隔，“重新连接”位于两条竖线正中。

主页七张卡片的标题统一为22像素、700字重、33像素行高。  


### 开发技术

| 技术 | 用途 |
| --- | --- |
| Python 3.11+ 标准库 | 后台调度、线程、本机 HTTP 服务及文件日志，无第三方 Python 依赖 |
| SQLite（WAL） | 配置、计划、发送防重复记录、事件及每分钟额度采样 |
| 官方 Codex CLI / App Server | 通过已登录的 ChatGPT 账户，以 JSON-RPC 读取额度和发送简短请求 |
| HTML、CSS、原生 JavaScript、SVG | 中文本地网页、响应式布局、时间轴拖动、额度圆环及折线图，无前端框架或外部图表依赖 |
| 浏览器 localStorage | 长期保存统计时间范围和额度类型，刷新及重开恢复 |
| PowerShell、Windows 任务计划、快捷方式 | 安装、覆盖更新、启动管理及登录自启 |
| Python unittest、Node.js node:test、GitHub Actions | 调度、HTTP、日志、采样及界面回归，Windows CI |

开发检查：`python -X utf8 -m unittest discover -v`、`node --test test_ui.cjs`；打包：`python -X utf8 build_release.py`。Node.js 用于安装 Codex CLI 和运行界面测试，页面本身不依赖 Node.js 服务。
