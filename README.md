# 额度启程 · Quota Starter

当前预发布版本：1.6.0-pre.5；最新正式版：1.5.23


Quota Starter 是一个 Windows 后台工具，用于查看 ChatGPT Plus 的 Work / Codex 共享额度，并在额度刷新后尝试发送一次简短请求。你也可以选择希望的刷新时间，由软件提前五小时安排请求。

软件提供中文本地网页界面，支持自动检测、定时刷新、预设任务、暂停运行和登录自启。关闭网页后，后台仍会继续运行。

## 安装

### 1. 准备运行环境

需要 Windows、Python 3.11 或更高版本，以及官方 Codex CLI。安装程序不会自动安装这些依赖。

1. 从 [Python 官网](https://www.python.org/downloads/windows/) 安装 Python，安装时勾选 **Add python.exe to PATH**。
2. 从 [Node.js 官网](https://nodejs.org/) 安装 LTS 版本，它包含 npm。
3. 打开 PowerShell，依次运行：

   ```powershell
   npm install -g @openai/codex
   codex login
   ```

4. 按浏览器提示，使用你的 **ChatGPT Plus 账户**完成登录。已有上述环境且已登录的用户可直接下载安装包。

pre.3按用户授权修复连接：优先使用npm官方Codex CLI；为子进程传递明确代理，避免重复系统代理/PAC发现。默认本地端口仍为8769，保留账户和防重复发送校验。

### 2. 下载并安装

1. 测试本次更新请打开 [1.6.0预发布下载页](https://github.com/Symplatt/codex-quota-starter/releases/tag/v1.6.0-pre.5)；[最新正式版下载页](https://github.com/Symplatt/codex-quota-starter/releases/latest)仍提供1.5.23。
2. 在 **Assets** 中下载 `quota-starter-版本号-windows.zip`，不要选择 `Source code`。
3. 右键 ZIP，选择 **全部解压**。
4. 打开解压后的 `quota-starter` 文件夹，双击 **Install.cmd**，等待安装完成。不要直接从压缩包窗口运行。
5. 双击桌面或开始菜单中的 **Quota Starter**，打开软件界面。

默认安装位置为 `%LOCALAPPDATA%\Programs\QuotaStarter`（通常为 `C:\Users\用户名\AppData\Local\Programs\QuotaStarter`），安装后会在登录当前 Windows 用户时自动启动。软件信息显示各自实际安装路径；本机开发使用的源码目录不影响其他用户的默认安装位置。当前使用脚本安装，没有 EXE 安装向导。仅解压文件不代表已安装成功；安装报错时请保留窗口中的错误信息。

### 从旧版本升级

下载新版 Windows ZIP，完整解压后运行新版 **Install.cmd** 即可覆盖安装，无需先卸载。安装会刷新程序缓存，已有历史记录、时间计划、暂停状态和自启设置会保留。

## 开始使用

页面标题下方仅在发生错误时显示横幅，展示后台已有的连接错误、自启错误或操作错误；对应错误恢复后隐藏，不显示历史错误。CLI接口不兼容时显示当前程序路径、版本与升级命令；断联保留上次额度，并明确标注旧数据。

通过 **Quota Starter** 快捷方式打开界面；后台运行时也可访问 [本地页面](http://127.0.0.1:8769)。主页保留“定时刷新”和“运行状态”两张等宽卡片，日期与时间按北京时间显示。标题右侧的操作控件垂直居中；卡片横向、纵向间隔统一为20像素。页面和日志使用细滚动条。

“日志”卡片汇总最近50条操作、连接及小额请求记录，包括计划的原/新时间、手动检测、重连、暂停、自启、连接故障与恢复，以及小额请求的结果和周期验证；未完成的预留请求也会显示。每分钟定时额度读取不进入此列表。日志卡片随已有记录的实际内容高度收紧，最多占网页可视高度减去上下各20像素留白，点击“日志”标题平滑定位到完整卡片，三列首行文字顶端对齐，记录在卡片内独立滚动；完整月度统一日志通过标题右侧按钮打开。正式版默认固定使用8769端口；桌面快捷方式、登录自启及诊断均连接同一个后台。正常连接运行时显示“后台运行”，暂停时显示“停止运行”。

正常连接时，每轮检测或发送结束后等待60秒再自动检测，临近或越过刷新时间也不加快频率。手动“重新检测”、“重新连接”和暂停后“恢复运行”会立即读取五小时与周额度，成功后恢复60秒间隔；失败重试仍间隔10秒。时间计划在到点后的下一轮自动检测中处理，保存或取消计划不会额外触发检测。如果当前窗口已经有实际使用，软件通常跳过额外请求；暂停状态下需要点击 **恢复运行** 才会继续发送。

| 操作 | 用途 |
| --- | --- |
| 选择时间 | 设置希望的刷新时间，软件自动提前五小时安排请求 |
| 恢复自动 | 取消手动计划，重新按服务器报告的刷新定时刷新；有待执行计划且按钮可用时与“选择时间”的文字颜色、字号、字重、行高和字距一致；没有计划时灰淡且不可点击 |
| 重新检测 | 只重新读取当前额度和服务器刷新时间，不发送小额请求，不提前执行时间计划；暂停时也可使用 |
| 重新连接 | 清除连接重试计数，先连接并读取额度，再交回后台调度；网络故障会自动重连，也可手动立即重连；暂停设置与发送记录保留 |
| 暂停 / 恢复运行 | 暂停发送，默认同时停止自动检测额度；恢复后继续调度，已提交的请求可能继续完成 |
| 关闭软件后依然每分钟检测额度变化 | 默认关闭；开启后，暂停期间仍在每轮完成60秒后只读检测额度并更新折线图，不发送小额请求 |
| 开机自启动 | 在页面下方设置登录 Windows 后是否启动；关闭此开关不会停止当前后台 |

定时刷新与运行状态卡片统一在标题右侧显示操作按钮；标题字号较大，窄窗口自动将按钮换到标题下方。并排时卡片等高，底部分隔线对齐。两张卡片的五个操作采用无底色、无常驻边框的文字按钮，悬停时显示下划线；运行状态按钮从左到右为“重新检测”、“重新连接”和“暂停 / 恢复运行”。定时刷新使用固定长度的横向时间轴，上方显示额度刷新与预计再次刷新，下方显示发送请求，每个事件保留北京时间和日期；等待超过五小时时以断轴符号省略部分距离，短间隔按比例显示，相邻事件保留最小可见间距。时间轴三个事件的圆点外径均为14像素，两个刷新节点保留原灰绿色空心样式，发送请求节点保留墨绿色实心样式和拖动操作；三个事件采用统一信息块，首个额度刷新节点卡与“定时刷新”标题左对齐，发送请求节点通过竖线连接信息卡，两端延伸刻度范围，刷新节点向内收，留出左右余量。时间轴带尺子式长短刻度，整点用灰色小字标注；断轴省略中间时段，窄窗口自动减少整点标注以避免重叠。两张卡片等宽等高；运行状态并列显示上次和下次检测时间，悬停时可查看完整日期；底部保留简要状态，鼠标悬停可查看完整原因，操作结果显示在页面右下方，成功提示3.5秒后关闭，错误提示7秒后关闭。窄窗口自动上下排列，并按内容收紧卡片高度。

“重新检测”、“重新连接”、“暂停 / 恢复运行”的可用文字为灰绿色；不可用时仍灰淡显示。

小额请求的状态、原因和周期验证统一显示在日志中。请求前后刷新时间相差不超过5秒时说明刷新时间未变；请求完成、原刷新时间已过且服务器返回约五小时倒计时时说明已进入五小时倒计时。其他变化或核验失败按实际结果显示，历史原始证据保留。额度检测、操作、连接及小额请求共同写入每月同一份 JSONL 文件；页面隐藏的每分钟额度检测仍完整写入文件。旧触发归档按事件编号去重合并，原档逐字节备份为 `.bak` 后移除旧 JSONL，格式无效或编号冲突时保留原文件并重试。

设置中的“关闭软件后依然每分钟检测额度变化”控制点击“暂停”后的检测；关闭网页不等于暂停或退出后台，后台进程退出、电脑休眠或关机后无法继续检测。默认关闭时，暂停期间不产生自动额度请求和新采样点，折线图保留已有数据；手动重新检测和重新连接仍然可用。该设置保存到本机，重启后保留。

### 设置刷新时间

点击 **选择时间**，窗口提示“选择**完成刷新**的时间”。输入年、月、日、时、分，或滚动各列选择数值（滚轮响应间隔由90毫秒缩短至30毫秒），然后点击 **确定**。秒固定为 `00`。取消、按 Esc 或点击弹窗外侧不会保存。

例如，选择 10 月 11 日 12:00 刷新，会安排 10 月 11 日 07:00 发送请求。主页时间轴显示服务器额度刷新、请求发送和预计再次刷新的时间。

“发送请求”的圆点始终保持不透明墨绿色。也可左右拖动该圆点，以十分钟为一格调整发送时间，预计刷新时间同步保持在发送后五小时，松开保存。原时间为03:33时，首次向左吸附至03:30，向右吸附至03:40；方向键左右也可调整，取消拖动不保存。弹窗仍支持任意整分钟。检测过程中可选择或拖动时间，保存与恢复自动操作按提交顺序排队，检测结束后按最新额度校验并应用；正常排队不显示错误横幅，保存请求尚未返回时不能重复提交。

不可用时间会灰置：推算出的发送时间须晚于当前时间和最近检测到的服务器刷新时间，且不早于防重复保护结束时间，并在未来 366 天内。未检测到服务器刷新时间时，选择按钮不可用。

待执行的手动计划优先于额度恢复后的自动发送。额度恢复且五小时使用量为0%时，即使服务器刷新时间滚动到五小时后，仍保留计划并等待设定的发送时间；例如03:00恢复、计划03:30发送，不会在03:00后提前发送。

每次定时检测、重新检测及发送前校验都会检查计划：五小时窗口已有使用，且服务器刷新时间达到或超过计划发送时间时，自动取消任务并恢复自动安排。手动重新连接或连接失败后恢复成功时，额外用本轮新读数检查：若待执行计划的发送时间严格早于五小时额度刷新时间，即使额度为100%也取消计划并恢复自动；相等且额度空闲时保留计划。取消后在右下角提示“定时计划已失效，已恢复自动”，同一计划不重复提示。重连核验这轮不发送小额请求；自动安排交回原有调度。启动时仅按原规则检查已有快照，缺少使用量时等待新读数。

到点发送仍须满足额度、暂停状态及防重复条件。睡眠、关机或断网可能造成延迟；预计刷新时间按发送时间加五小时计算，实际刷新以服务器返回为准。

### 周额度预计更新时间

周额度下方仅用一行显示预计更新的北京时间：距离更新不少于24小时显示日期（YYYY/MM/DD），不足24小时显示时分秒（HH:mm:ss），悬停可查看完整日期时间。“重新检测”“重新连接”“恢复运行”每次成功读取后均更新周额度恢复时间，不要求五小时额度已满。每次检测到五小时剩余额度100%，紧接着再读取一次额度，用这次新响应同步更新两个窗口及周恢复时间；连续100%的各轮也会补读一次，不递归补读。普通非满额自动检测保留最近记录的周恢复时间，各账户分别保存。该次未返回周时间则显示“预计更新待检测”，未返回周额度则显示“未返回额度”。补充读取沿用同一个额度接口、账户校验与失败重试，不发送模型请求，每轮结束后仍等待60秒再自动检测。

### 额度变化统计

统计卡位于两张概览卡片下方、日志上方。以默认最大化的电脑浏览器网页可视高度（不含浏览器工具栏和系统任务栏）为100vh；软件标题、定时刷新卡、运行状态卡及留白均保持既定尺寸，只调整额度变化统计卡高度，使统计卡底部加20px留白与100vh对齐，预设任务从首屏下方开始，日志位于其后。顶部错误横幅出现或增高时，统计卡保持相同窗口下无横幅时的高度，整张卡片向下顺延；横幅消失后恢复原位置。高度较小时统计卡继续缩小，不再因剩余高度不足140px而变高；若窄屏上下排列的固定内容本身已超出可视高度，则保留滚动，不压缩这些固定内容。

细折线显示每分钟剩余额度；可切换五小时或周额度，以及最近一小时、五小时、二十四小时。横轴细刻度随范围变化，纵轴范围固定为0%至100%，不随采样值变化；绘图区高度不足200px时每20%一个刻度，达到200px时每10%一个刻度；曲线穿过每个真实采样点，平滑连接不产生超出采样的峰谷，曲线始终为墨绿色，快速消耗直接体现为陡降，不显示图例或变色，缺测不连线。标题与图表之间保留24像素留白；悬浮标签固定两行，第一行是日期时间，第二行是剩余额度和分钟变化，消耗和恢复的百分点按整数显示。两个选框会在当前浏览器中长期保存上次选择，刷新或重新打开页面时自动恢复。

统计复用现有检测，不额外发送模型请求；同一分钟以最后一次读取为准，关闭网页或重启后台保留采样。休眠、断网或未检测的分钟留空，跨缺口不计算变化；只显示当前账户的采样，升级前未采样的历史不补造。变化按服务器返回的百分比计算，单位为百分点，不代表精确 Token 数；检测仍在每轮完成后间隔60秒。

点击“重新检测”“重新连接”或暂停后“恢复运行”，均会从同一份最新响应同时更新五小时与周额度；继续运行先进行只读检测，不额外触发小额请求。

## 预设任务

“额度变化”下方的“预设任务”卡片可添加一次性 Codex 任务。状态每2秒独立更新，不改变原有每轮结束后60秒的额度检测节奏。

1. 默认 MD 目录为 `%LOCALAPPDATA%\QuotaStarter\tasks`（通常位于 C 盘用户 AppData\Local），首次使用时自动创建；可在“任务设置”改为其他目录，清空后恢复默认。打开设置会检测本机 Codex 提供的其他模型，以标签复选，支持重新检测；保留 GPT-6 Astra、GPT-6.1 Sol 默认选项。
2. 新建任务时填写名称，选择精确到秒的北京时间，或五小时额度回满后立即执行。已回满时立即校验，到达旧刷新时间后仍重新核对额度，未满则继续等待。
3. 选择模型及 low、medium、high、xhigh、max、ultra 强度。执行前检查本机模型目录，不支持的模型或强度会显示失败原因，不自动替换。
4. 填写内容生成新 MD，或读取已有 UTF-8 MD（最多200 KB）。可手填绝对路径或打开原生路径选择窗口。设置默认目录后，文档路径留空即可自动生成独立文件，已有文档不会覆盖。
5. 选择执行目录，留空使用 MD 所在目录。Codex 可在执行目录内修改文件，采用 workspace-write 沙箱，不自动批准越界操作；隔离其他用户配置，仅沿用已有 Windows 沙箱后端；请先在官方 Codex 完成 Windows 沙箱初始化。任务使用已登录的 Plus 订阅，会消耗额度。

任务开始前只读连接遇临时故障，最多尝试5次、总时长60秒；已提交的任务不自动重试。

任务依次执行，标题下方显示“任务状态每 2 秒更新”；列表按名称、模型与强度、开始时间、状态胶囊和操作分列，状态不重复显示。状态胶囊与任务设置按钮右对齐，详情相对新建任务按钮右边缘向左偏移6px，作视觉对齐。新建窗口先选择模型与强度，再设置开始方式和时间，字段小标题加粗、表单行间距为26px。详情显示创建时保存的内容、持续更新的回复、错误、开始及结束时间；成功后在 MD 旁生成独立 `.result.md` 结果文档。修改原 MD 不影响已创建任务。

详情弹窗的状态胶囊位于标题右侧，与标题等高，文字较小且居中；相同的状态与进度不重复显示，具体进度和失败原因保留。任务及结果文档在执行目录内时显示为 `...\相对路径`，悬停元信息可查看完整路径；目录外文档保留绝对路径。

等待任务可取消，运行任务可中断，已产生的修改保留。全局暂停阻止新任务开始，不撤回运行中的任务。网页关闭后后台继续调度；关机/休眠时不能执行，重新启动后到期任务依次执行。执行中后台退出或未确认完成时保留结果未知记录，不自动重新提交；请先检查执行目录。任务及设置保存在原 SQLite 内，覆盖升级时保留。

右侧留白足够时显示定时刷新、额度变化、预设任务、日志、设置五个导航节点。点击“定时刷新”返回整页最顶部；其他节点和可点击标题定位时保留顶部20px留白，避免露出上一张卡片。设置卡片受页面高度限制时仅滚动到自然底部，不添加额外占位留白。节点显示阅读位置；窄窗口隐藏侧边节点，标题仍可定位。时间轴箭头末端与“额度再次刷新”卡片右边缘对齐。

## 运行条件与请求开销

软件使用已登录的官方 Codex CLI 读取额度并发送简短请求，不使用 API Key。发送会消耗订阅内额度，实际开销以记录为准；短提示词仍可能包含官方运行时添加的上下文。

软件不会增加总配额、突破五小时或每周限制、购买积分或使用额度重置券。额度不足、登录不符合要求或额度信息无法确认时，不会发送。

请求已能实际完成，但“刷新后的首次请求是否决定下一轮五小时起点”尚未完成跨自然刷新边界的验证，因此不能保证按所选时间刷新。机制依据见 [机制说明](MECHANISM.md)，已有测试见 [验证记录](VALIDATION.md)。

自动运行需要电脑开机并登录当前 Windows 用户。锁屏时可继续运行；休眠、关机或断网时无法发送。无需一直打开网页或 Codex 桌面窗口。

每轮连接、检测或发送最多尝试5次（含首次），失败后间隔10秒，从首次尝试起最多1分钟。只读连接的临时故障在一轮耗尽后，按30、60、120、240、300秒退避，之后最长每5分钟再发起一轮有界恢复；成功后清零并恢复每轮结束后60秒检测。重启保留等待时间，升级会将旧20分钟等待缩短至最多30秒。恢复轮先只读校验，下一轮才处理仍有效的计划。身份、数据或CLI接口不兼容错误不进入无限自动恢复；未知发送结果继续停止并保留防重复保护。

连接完成后即更新额度，另行显示准备、发送及核验请求的状态。重新检测在后台执行，不等待小额请求完成；自启动状态查询不会阻塞额度显示。

代理来源依次为QUOTA_HTTP_PROXY、当前启用的Windows代理、继承的环境变量；localhost、127.0.0.1和::1保留直连。关闭CLI重复的系统代理/PAC发现及引导回退；无明确代理时使用CLI默认网络路由。仅有PAC配置时可通过QUOTA_HTTP_PROXY提供明确代理。只读HTTP临时错误在当前有界轮次内复用健康进程；本地RPC超时、管道断开、进程退出或整轮耗尽时重建。HTTP 408/425/429/500/502/503/504可恢复，认证失败和账号变化仍停止。软件不修改系统代理或Codex配置，不读取或复制认证文件。

软件信息显示名称、版本、当前后台程序的实际安装路径及版权声明“版权所有 © 2026 Symplatt”；从源码运行时，安装路径显示源码目录。

## 停止与卸载

- **暂时停止发送**：在页面点击“暂停”，状态在重启后保留。
- **停止当前后台**：运行安装目录的 `Stop.ps1`；自启开启时，下次登录仍会启动。
- **取消自启并停止后台**：运行 `Uninstall-Autostart.ps1`。
- **卸载**：运行 `Uninstall.ps1`，移除自启及快捷方式。程序文件与数据会保留，需要彻底删除时，再自行删除安装目录。

将 `%LOCALAPPDATA%\Programs\QuotaStarter` 粘贴到文件资源管理器地址栏即可打开安装目录。右键所需 `.ps1` 文件，选择“使用 PowerShell 运行”。执行策略阻止脚本时，可在该目录打开 PowerShell，运行以下命令，将文件名替换为所需脚本：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Stop.ps1
```

该命令只影响当前进程，不修改系统全局执行策略。

## 常见问题

| 问题 | 处理方法 |
| --- | --- |
| 安装提示找不到 Python 或 Codex | 检查依赖安装，重新打开 PowerShell，执行 `python --version` 和 `codex --version` |
| 页面打不开 | 从快捷方式重新启动，检查安装目录的 `data\supervisor.log`；确认本地端口 8769 未被占用 |
| 提示不是 ChatGPT Plus 登录 | 用 `codex login status` 检查登录，运行 `codex login` 登录 Plus 账户 |
| 无法获取额度 | 检查网络与官方服务；网络故障按30秒至5分钟退避后自动重连，也可点击“重新连接”立即重试 |
| 到点仍未发送 | 检查暂停状态、每周额度和防重复记录；服务器仍报告额度用尽时会继续等待 |
| 提示轻量模型不可用 | 更新官方 Codex CLI 后重新检测；软件不会自动切换到高消耗模型 |
| 登录后没有自启 | 检查页面自启开关和 Windows 任务计划程序中的 `QuotaStarter-WorkCodex`；确认 Python 未被移动或删除 |
| 无法设置自启 | 检查是否受 Windows 或企业策略限制，保留安装错误信息 |

进一步诊断：在安装目录打开 PowerShell，运行 `python -X utf8 diagnose.py`，该命令不发送请求。提交问题前请检查日志，移除不希望公开的信息。

## 数据与隐私

### 统一 JSONL 日志

点击“日志”卡片右上角“打开日志文件夹”，打开 `%LOCALAPPDATA%\Programs\QuotaStarter\data\logs`。额度检测、操作、连接、小额请求结果及周期验证统一写入按北京时间月份保存的 `quota-starter-YYYY-MM.jsonl`，每行一条完整事件。页面不显示的每分钟自动检测也照常写入；页面最近50条限制不影响文件归档。

升级时把旧 `data\triggers\quota-triggers-YYYY-MM.jsonl` 合并到同月统一日志，按事件编号去重，并保留旧档的扩展证据。原文件校验备份到 `data\legacy-archive-backups`（`.bak`）后删除旧 JSONL；异常文件保留并重试，不覆盖证据或丢弃数据。无关文件不动。旧 `/api/triggers/open` 接口兼容打开统一日志目录。

月度日志按北京时间只保留本月、上月和上上月，每月1日清理更早文件；月初未运行时，下次启动或写入补清理，失败自动重试。数据库先保存完整事件，再同步归档。异常断电发生在写入与进度保存之间时，普通追加可能出现相同事件 ID 的重复行。使用自定义 `--data` 时保存在该目录的 `logs` 下。

定时刷新与运行状态采用等宽卡片，卡片间距20像素，卡片左右内边距与“日志”卡片一致，均为24像素，时间轴上的三个时间小卡等宽、最大190像素；运行状态以环形进度显示“五小时额度”和“周额度”，并并列显示上次、下次检测时间。顶部操作使用独立竖线分隔，“重新连接”位于两条竖线正中。

主页六张卡片的标题统一为22像素、700字重、33像素行高。
